# 排行榜分类、审核与日期管理

用户要求将游客榜和注册用户榜分开，游客昵称以 `visitor` 开头，游客成绩默认待审核且管理员可调整，注册用户的普通成绩默认直接发布，管理员仍可驳回。管理员还需控制榜单展示期限并按日期清理排行榜。

2026-11-15 对现有生产站点仅做匿名汇总和公开接口只读检查：三条游客公开成绩仍在数据库，分属不同语言、难度及时长，对应筛选接口均返回；无相关管理员下架事件。尚不能据此断定用户曾观察到的所有消失现象都由筛选造成。现有界面重建时默认条件可能变化，因此以真实页面复现并让筛选条件可分享、刷新保留；不使用生产用户数据测试。

1. 扩展站点设置，旧 JSON 和旧管理页面更新不能抹掉新配置。默认游客审核、注册用户普通成绩直接发布；既有反作弊和恢复练习审核继续生效。展示期限默认不限制，只影响公开显示，不自动删除。
2. 服务端强制游客昵称前缀，榜单按游客／注册用户分类；前端显示条件和成绩时间，筛选写入稳定 URL，刷新及跨浏览器打开同一链接保持一致。
3. 成绩后台支持日期、身份筛选与发布成绩驳回。日期范围清理先预览匹配数量并计算快照，提交时在事务内复核快照、权限和原因，再撤下公开成绩并写审计；个人练习历史保留，筛选结果变化时拒绝静默覆盖。
4. 分别以隔离 SQLite 和 PostgreSQL 测试权限、默认值、旧设置兼容、审核、拒绝、并发变更、日期边界和筛选；浏览器验证游客与账号、刷新、跨浏览器、后台配置和批量操作。记录仍未复现的线上现象，不能将猜测写成已证实根因。
