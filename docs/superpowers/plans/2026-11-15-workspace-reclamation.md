# 工作区删除标记回收与旧设备恢复设计

目标：释放删除标记占用的工作区项目配额，同时阻止离线旧设备或旧客户端自动复活已删除项目；旧设备未同步内容在用户选择前保留且可导出。以下为实施前设计，尚未完成的要求继续留在需求跟踪表。

## 协议边界

1. 服务端按账号保存单调递增的同步代次和项目修订号；读取响应携带协议版本、代次和每项修订。写入必须携带当前协议版本、代次与项目所依据的服务端修订。旧客户端或缺少协议的写入返回明确的更新提示，读取仍可用于恢复或导出。
2. 写入、修订检查、配额检查、删除标记回收和代次递增均在 SQLite 立即事务内完成。代次或项目基准不匹配时拒绝该写入，不采用客户端时钟猜测先后。客户端保留本机内容并报告冲突。
3. 同一代次内，已同步项目的删除标记优先于离线设备上未改变的旧副本；若本机自上次同步后也修改了该项目，保持本机副本并提示冲突，不能静默覆盖或自动复活。主动重新创建需要显式用户操作和服务端可验证的删除基准。
4. 回收删除标记时增加代次。旧代次设备不得上传任何本机项目；在用户选择前保持其本机工作区、旧版草稿和记录，提供仅本机的版本化导出。用户明确确认后，可用服务器全量快照替换本机缓存并更新代次；此过程不得改写其他账号或游客资料。
5. 草稿删除不仅影响工作区：在线挑战恢复路径也须永久识别已删除的草稿。回收时保留最小的草稿删除登记，或以等价方式使恢复接口拒绝旧草稿；该登记不计入工作区 2,000 项额度。历史成绩和公开文章快照不因此改写。
6. 未能安全保存代次或本机恢复资料时，停止云端写入并提示更新／导出；不能通过重试自动绕过代次检查。新账号或没有本机数据的设备可安全采用当前代次。

## 实施与验证顺序

- [ ] 为服务器增加幂等迁移和代次／修订事务，验证旧客户端拒写、批次原子性和容量统计。
- [ ] 在客户端模型、本地解析、同步合并及服务器校验中引入同一套修订字段，覆盖旧数据与新旧客户端交替。
- [ ] 先实现本机仅导出和显式重同步保护，再启用回收入口；未同步内容不得在提示前删除。
- [ ] 联动挑战恢复路径，验证已删除草稿在标记回收后仍不可恢复上榜。
- [ ] 测试设备 A 删除、设备 B 离线重连、回收后旧设备重连、并发回收与写入、重新创建、容量释放及新项目同步。
- [ ] 运行两浏览器真实流程、迁移／备份恢复及完整回归，记录协议升级和回退注意事项。
