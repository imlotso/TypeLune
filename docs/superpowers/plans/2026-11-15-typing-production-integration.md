# typing 生产兼容与剩余验收计划

**目标：** 完成任务书 A—F 的剩余功能和验收，将已实现的训练体验与现有 Vercel／Neon 生产架构安全整合。

**架构：** 保留 React、逐行输入与本机 SQLite 运行方式，复用线上 `codex/vercel-neon-postgres` 的异步存储接口、连接池和同源 Vercel Function。账号、反馈、工作区及成绩使用同一套业务行为；PostgreSQL 模式升级必须显式、版本化、可重复并兼容已有数据。

**基线：** 升级分支 `0073894c2783fc1b24bdc1465d5e927353594a0d`；线上 Vercel 发布版本 `06a9e5139abd8dc43d107649b468f5e992021fea`；原需求及验证证据见 `docs/qa/2026-11-15-typing-upgrade-tracker.md`。

## 约束

- G01—G04 继续后置；保留输入法、长文恢复、账号隔离、服务端审核和现有视觉。
- 保留 `.openai/hosting.json`、`worker/index.js`、`scripts/prepare-sites-build.mjs`、`tests/sites-worker.test.mjs`。
- 不用生产用户数据作为测试素材；不重建、覆盖或清空现有生产数据库，不输出连接串和认证材料。
- SMTP 接通和实际邮件送达分开验证，运营主体、联系信息和政策日期不得编造。
- 只针对 `typing.imlotso.com` 清理缓存；当前 Cloudflare DNS 未代理，需确认缓存实际所在层。

## 可验收任务

1. **剩余本机边界**：针对旧记录标识碰撞、离线副本和跨存储清理补充可复现测试与实现；核对不支持 Navigation API 的前进／后退与未保存内容保护。对浏览器无法提供的保证，明确说明实际行为。
2. **整合现有部署分支**：合入 Vercel 和 PostgreSQL 适配，逐项解决冲突；保留同步分页、请求体上限、错误处理、SQLite 本地体验及全部 A—F 业务。
3. **迁移与数据完整性**：设计从现有 PostgreSQL 版本到新版本的增量迁移；账号、反馈附件、工作区代次与删除登记、成绩快照及审计均须验证。迁移仅在显式命令中执行，不在函数启动时自动修改生产 schema。
4. **隔离测试**：使用新建的本机临时 PostgreSQL 和虚构账号运行迁移、并发、权限、附件、删除与重试测试；同一浏览器流程分别覆盖 SQLite 与 PostgreSQL，测试失败不进入生产。
5. **准备生产交付**：在隔离预览验证实际 Vercel Function、Neon 连接、回滚和备份；核对正式 SMTP、站点运营配置、远程 CI 和实际邮件送达，记录无法验证的项。
6. **生产切换与缓存**：仅在主体验收、备份、迁移及预览验证完成后，部署并确认生产端到端行为；按已确认的单个网站地址执行最小范围缓存清理，记录实际结果。
