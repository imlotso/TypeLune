# TypeLune 性能与稳定性审计

审计基线为 7eeaf25，候选包含本次 P0、P1 与 P2 修复。性能在同一台云工作机与相同 Chromium 配置重测。API 与浏览器均连接回环测试库，文中指标是实验室数据。生产 RUM、边缘 TLS 与实际跨区域延迟需在授权环境采集。 [Web Vitals](https://web.dev/articles/vitals) · [INP](https://web.dev/articles/inp)

- **目录响应**只压缩公开、没有会话内容的文章目录。正常 JSON、分页、未协商压缩的客户端和 no-store 语义均保留。最终采用 gzip level 1，因为同一 502 KB 样本压缩基准中，level 1 的 p50 为 8.5 毫秒且约 236 KB，默认级别约 22.4 毫秒且约 215 KB。最终应用实测目录正文 501,712 → 236,321 B，节省 52.9%。压缩会增加少量服务端处理时间，见后面的 API 表。 [文章接口](../server/app.ts#L791) · [压缩回归](../tests/web-hardening.test.ts)
- **静态资源**主 JS 的原始体积约 1.268 MB、Brotli 约 393 KB，CSS 约 91 KB、Brotli 约 17 KB。React、首屏及首次离线导航所需模块、内置文章的体积仍集中在首包。后台、公开个人页和排行已有独立 chunk。当前保留离线第一次打开文章库、历史和草稿的契约，未把所需模块改成离线时无法取得的独立请求，也未删除仍用于测试或资产来源的文件。生产构建的大 chunk 告警仍存在。 [入口](../src/App.tsx) · [离线导航回归](../e2e/offline-pages.e2e.ts)
- **缓存与图片**Fastify 实测散列静态文件为 immutable，Brotli/Gzip 预压缩按 Accept-Encoding 提供且能正确解码。已修复全局 no-store 覆盖公开 WebP 壁纸浏览器及其他代理 TTL 的问题。200 WebP、公共路由且无 Set-Cookie 才允许共享缓存。无效尺寸、上游或转换失败、个人背景和私密 API 继续 no-store。Vercel 专用头继续由函数处理，Vercel 与外层 CDN 命中仍需环境验收。默认湖景首屏约 32 KB，现有壁纸宽度变体、内存上限、在途去重和头像缩略尺寸已保留。未删除仍用于测试的 PNG 或影响 IndexedDB 自定义背景。 [静态资源回归](../tests/web-hardening.test.ts) · [壁纸回归](../tests/wallpaper-images.test.ts) · [Vercel 缓存头](https://vercel.com/docs/caching/cache-control-headers)

## P02、P03 与 P09 · 打字、离线和同步

实时指标原来在计时变化后对已输入字符再分段、计数。现用已有的 NFC 字素数组按输入或续练偏移重算计数，计时更新只重算速度。中英文、组合字符、Unicode 符号、续练偏移及超出目标的输入以相同规则计分。持续输入中的每次文字变化仍产生必要渲染，现有长行分窗、IME 确认和练习持久化策略保持原样。 [实时指标](../src/App.tsx#L407) · [计分](../src/lib/scoring.ts) · [计数一致性测试](../tests/typing.test.ts)

同一 Node 22 进程对 9,000 个目标字素、8,001 个输入字素和续练偏移 120 的固定状态测量 7 组，每组 60 个计时更新。旧实现中位数为 5.33 毫秒/次，新实现低于 0.01 毫秒/次。所有 60 个时点的分数逐字段一致。该微基准只度量计时更新中的计分计算，UI 交互结果另列。

工作区保存、网络错误恢复、离线重试、跨设备版本冲突、删除标记和账户切换由既有队列及验证处理。本地回归涵盖合成中文 composition、英文练习、快速逐键、暂停续练、跨设备草稿和重复提交。当前用量控制、同步事务和重试节流路径未改动。选择逐键性能改动时保留成绩计算与写入语义。 [同步实现](../src/hooks/useWorkspace.ts) · [离线练习](../e2e/recovery.e2e.ts) · [输入法事件](../e2e/practice.e2e.ts)

## Q03 · 隔离恢复与 Preview 等价检查
