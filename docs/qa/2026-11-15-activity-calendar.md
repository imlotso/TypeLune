# 活动日历与统计时区阶段记录

- 日历使用全部已读取的中英文记录，以账号保存的 IANA 时区和完成时刻归属日期；一次跨午夜练习的全部已记录有效用时归入完成日，不推断过程中的分段用时。日历展示每天的次数、已知有效用时及可打开的记录。
- 当前连续天数从今天或仍连续的昨天向前计算；最长连续按可读取记录计算。本机或不完整覆盖时明确标为本机／已读取范围，不宣称全历史最长。未来记录不计入；没有有效用时的数据标为未知，目标未达到时不把未知用时视为零。已知用时达到目标时可显示已达成。
- `ReaderSettings` 新增可选 `statisticsTimezone` 和 `dailyGoalMinutes`（0 关闭，1–1440 为整分钟）。账号首次进入统计且云设置已读取时，缺少时区才采用浏览器时区并通过正常工作区同步；离线尚未保存时标明本机临时时区。目标与时区仅影响个人展示，不改变计分及排行。编辑期间收到其他设备更新时保留未提交内容并提示。
- 字段保存在现有工作区 JSON 中，服务端与本机均校验时区及范围；旧账号没有字段时使用浏览器时区，旧客户端保存其他设置时服务端保留新字段。显式游客资料导入可包含这两个设置，账号原设置仍按原有冲突规则保留。完整个人数据 JSON 导出包含它们；独立练习设置导入／导出仍只包含其既定白名单，不携带日历设置。
- 不新增 SQLite 表或列。部署前仍应通过 SQLite 备份 API／既有备份流程备份数据库、WAL 一致状态和持久化卷；前后端同步升级，旧服务会剔除未知设置字段，不能直接回退旧服务后继续写入而声称保留新字段。未操作生产数据库。
- 单元测试覆盖跨午夜、时区差异、夏令时切换、连续天数、未知用时及设置冲突；浏览器测试覆盖实际练习、日期记录、账号两设备同步和个人数据导出。`DAZI_TEST_IMAGE=typing-upgrade-ci:local npm run test:docker` 通过，验证设置在容器替换和数据库备份恢复后保留。已查看[桌面日间](screenshots/activity-calendar-desktop-light.png)与[手机夜间](screenshots/activity-calendar-mobile-dark.png)界面。最终全站回归和真实系统输入法验收仍待完成，F02 保持待完善。
