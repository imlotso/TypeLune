# 反馈模块实施说明

反馈正文、处理状态、公开回复、内部备注和附件均存入 SQLite。附件在服务端检查实际格式、大小及像素数，拒绝动画并重新编码为不含原始元数据的 WebP。每条最多三张，每张原图不超过 5 MiB。附件 BLOB 与反馈在同一事务保存，随 SQLite 数据库保存在既有 `DATABASE_PATH` 所在持久化目录；Docker 的 `/app/data` 卷和现有 SQLite 在线备份因此也包含附件，不需要独立文件卷。数据库空间会随附件增长，运营时需监控容量并备份；在内存数据库运行时资料仅存在于该进程。

`sharp` 是新增生产依赖，部署须使用锁文件安装受支持平台的可选二进制包。升级前按照 README 备份 SQLite 和 `CODE_SECRET`，确认新镜像及持久化卷可读写。回退前再次备份当前数据库；恢复旧备份会丢失备份之后的数据。后台审计表的目标类型检查通过事务迁移扩展为 `feedback`，历史审计行保留；旧版本不提供反馈界面和接口。

## 接口及权限

- `GET/POST /api/feedback`：当前用户的分页列表和创建。创建接受分类、标题、描述、可选公共文章快照及最多三张截图。客户端 `requestId` 用于同内容重试去重，不同内容重用同一 ID 返回冲突。
- `GET /api/feedback/:id`、`POST /api/feedback/:id/messages`：只允许提交者查看与补充；用户不能修改状态。公开线程包含状态变更及公开回复，不返回内部备注。
- `GET /api/feedback/:id/attachments/:attachmentId`：仅反馈提交者或当前有效管理员可读取，返回处理后的 WebP，禁止缓存和嗅探。
- `GET /api/admin/feedback`、`GET /api/admin/feedback/:id`、`POST /api/admin/feedback/:id/handle`：后台按分类、状态和 UTC 日期范围筛选；处理请求携带当前 `revision`，过期页面收到冲突而不覆盖新的处理。公开回复、内部备注与状态变更作为独立事件记录；审计只记录操作及反馈编号，不保存回复、内部备注或截图内容。
- 文章纠错只接受当前已发布文章及其快照标识，服务器核对后保存标题、ID 和快照标识，不自动接收私人文章正文。文章编辑仍走既有版本校验。

反馈处理结果通过站内详情交付，未实现反馈邮件通知。游客反馈表单通过内存交接保留到随后登录的账号；未提交的表单不会在关闭或刷新页面后持久化。账号注销通过数据库外键级联删除该账号的反馈及附件。
