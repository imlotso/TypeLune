# typing Vercel／Neon 整合记录

生产站点 `typing.imlotso.com` 对应现有 Vercel `dazi` 项目，当前生产部署基于 `06a9e5139abd8dc43d107649b468f5e992021fea`，使用 Neon PostgreSQL。该域名在 Cloudflare 的 DNS 记录当前未代理，实测响应来自 Vercel；不应清空整个 `imlotso.com` 区域的缓存。

## 数据与部署边界

- 合并现有异步 SQLite／PostgreSQL 适配，保留服务端事务、共享限流、Vercel Function 和 SQLite 本地运行。同步协议 2 的代次、项目修订、永久删除登记和账号隔离与分页快照同时使用；分页中断或版本变化不会将不完整数据写入本机。
- 已有 PostgreSQL schema 1 及其校验和保持不变；显式迁移按顺序应用 schema 2。新增昵称、会话信息、反馈、附件暂存、工作区修订和删除登记，迁移不在函数启动时自动执行。迁移只在本机隔离 PostgreSQL 测试，**尚未应用于 Neon 生产数据库**。
- 原生产版本只接受 schema 1；应用 schema 2 后不能假定旧 Function 可直接回滚。正式切换需要先完成可恢复备份、隔离恢复演练、写入协调和新版本预览验证，保留原 `CODE_SECRET`；任何一步失败均不得把测试库或空库指向正式站点。
- SQLite／PostgreSQL 迁移和导出覆盖新增表、反馈附件二进制、工作区代次和旧删除标记；SQLite 的 NUL 内部标记与 PostgreSQL 不允许 NUL 的文本格式使用可逆的保留值转换。测试只用虚构账号和独立本机数据库。

## 平台限制

- [Vercel Functions 请求及非流式响应上限为 4.5 MB](https://vercel.com/docs/functions/limitations#request-body-size)。文章、历史和工作区按小于 2 MiB 的页面读取；个人导出、游客导入核对及冲突恢复共用完整分页读取。
- 反馈截图以每块 768 KiB 的请求上传，按账号、请求和文件关联，检查块顺序、长度和 SHA-256；重复块可重试，不同内容冲突时拒绝。服务端核验图片并重新编码，单张结果不超过 3.5 MiB。暂存按账号限额、限请求数并在后续上传时回收过期块；成功提交和账号注销会清理关联暂存。
- Vercel Vite SPA 重写先处理 `/api/*`，其余页面回到前端路由，由前端实际识别文章、记录、反馈和未知地址。
