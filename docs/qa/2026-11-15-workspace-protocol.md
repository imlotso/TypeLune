# 工作区同步协议与删除标记整理

本阶段在原 SQLite 数据库上重复执行迁移：为 `workspace_items` 增加修订号，并增加按账号隔离的同步代次与已删除在线草稿登记。旧项目保留并以修订号 1 开始；已有用户、文章、成绩和草稿不因迁移被重建。

## 接口和行为

- 协议 2 的 `GET /api/workspace` 使用 `X-Workspace-Protocol: 2`，响应包含 `protocol`、`generation` 和每个项目的 `serverRevision`。普通读取仍返回原有结构，便于旧客户端读取和导出。
- `POST /api/workspace/sync` 除协议头外必须携带 `generation` 和每个项目的 `baseRevision`。旧版写入返回 `426 SYNC_CLIENT_UPDATE_REQUIRED`；过期代次或项目修订分别返回 `409 SYNC_RESYNC_REQUIRED`、`409 SYNC_CONFLICT`。一次批次的检查和写入在 SQLite 立即事务内完成，失败时不保留部分写入。
- `GET /api/workspace/usage` 返回工作区项目、删除标记、各类型数量和内容字节数，限额为 2,000 项和 32 MiB。这里的内容字节数不是数据库文件或备份的总磁盘使用量。
- `POST /api/workspace/compact` 检查当前代次，回收工作区删除标记并在有回收时递增代次。在线草稿的最小删除登记留在独立表，以避免历史恢复接口重新恢复被删除的草稿；此登记不占工作区项目配额，但会占少量数据库磁盘空间。
- 客户端在 IndexedDB／降级存储中保存项目同步基准和代次，并检查旧版草稿、记录以及旧标签页写入。旧设备或本机冲突不会自动上传；个人数据页可发起整理，设置中可查看同步冲突。本机资料先可单独导出，只有明确确认后才从云端快照替换当前账号的本机工作区与旧版练习缓存。其他账号和游客空间不受该替换影响。恢复导出保留可能与删除标记冲突的旧版草稿副本，但不包含认证、恢复密钥或会话材料。
- 整理后其他设备需要更新并重同步；永久离线设备无法被即时通知。若整理响应丢失，界面报告结果无法确认，用户可刷新容量或检查同步状态。网络故障不阻止本机练习。

## 备份、升级和回退

在测试或部署环境使用 SQLite 备份 API 或项目已有容器备份流程，备份完整数据库以及部署所需的配置和持久化卷；不要只复制正在写入的主数据库文件而忽略 WAL。先在备份副本上测试新版本及回退方案，再同步部署前端和后端。旧页面须刷新，否则其云同步写入会被拒绝，未同步内容应先导出。

未经整理时可在备份副本上验证回退；一旦删除标记被整理，旧服务不理解同步代次，**不能直接回退旧代码并继续接受写入**。要回退，应停止写入并从整理前的一致备份恢复，明确评估备份之后的数据损失，再验证旧版本；或先实现能保留删除基准的兼容回退。恢复前需另存当前数据库，不得以旧备份覆盖唯一副本。本次未对生产数据库执行迁移、整理或回退。
