# 账号资料阶段说明

## 接口

- `POST /api/account/username`：已登录账号提交 `username` 和 `currentPassword`；验证当前密码后，在立即事务中再次检查会话、身份版本、原用户名和唯一性。返回更新后的当前账号。
- `POST /api/account/password`：提交 `currentPassword`、`newPassword`、`confirmPassword`；使用 Argon2id 保存，事务中复核会话并撤销全部会话和该邮箱的旧验证码。调用方应回到游客空间并提示重新登录。
- `POST /api/account/profile`：提交 `displayName` 和 `avatar`。头像目前是内置的 `cloud`、`star`、`moon` 或 `null`（默认），不涉及图片文件或上传。账号菜单和公开榜单展示当前公开昵称；`challenges.nickname` 继续保存提交时快照。
- `POST /api/account/email/code`：已登录用户提交 `email` 和 `currentPassword`；通过后向目标邮箱发送用途为 `change-email` 的验证码。最多保留五个未过期目标，同一目标 60 秒内不能重发；发送失败删除对应待验证数据。
- `POST /api/account/email/confirm`：提交目标 `email` 和 `code`；服务端在事务中检查账号、目标、期限、次数和邮箱唯一性，然后更换邮箱、撤销会话并清理相关验证码。验证码只保存带账号和用途的 HMAC，不作为 API 响应返回。
- `GET /api/account/sessions` 返回当前账号的有效会话、粗略浏览器／系统、创建时间、最近请求时间和当前设备标记。`POST /api/account/sessions/revoke` 按公开会话 ID 撤销指定设备；`POST /api/account/sessions/revoke-others` 保留当前设备并撤销其他会话，同时阻止撤销前已开始的密码验证重新创建会话。接口不返回会话令牌或令牌摘要。
- `POST /api/account/delete` 验证当前密码，并在立即事务中重新校验会话、认证版本和最后一位有效管理员限制。事务删除账号、工作区、反馈及附件、在线练习和成绩，撤销会话与验证码，并匿名化相关管理审计。前端在注销前提供导出与明确确认，完成后清理本机缓存；响应丢失时不声称注销成功。
- 注销或清理前记录本机待清理标记；若本机清理未完成，游客页面可在刷新后重试。明确登录仍存在的账号会解除标记，用户可再次选择清理。
- 请求沿用同源检查、Cookie 和速率限制；页面传入 `X-Workspace-Owner` 以避免旧页面误操作切换后的账号。密码不会出现在成功响应中。
- 注册、验证码登录及找回密码请求对有效邮箱采用相同的发送及错误响应；不符合当前账号状态的请求收到不可用于认证的验证码，以减少通过重发和邮件服务错误枚举账号的机会。仍受请求频率限制。

## 数据与兼容

启动时以幂等迁移为 `users` 添加 `display_name`、`avatar`；缺失昵称用迁移时的用户名初始化，默认头像为 `NULL`。新账号创建时写入昵称。迁移不会改写用户 ID、工作区或既有成绩；工作区同步协议未变。旧前端仍可登录，但不会展示或修改新增资料，回退旧服务时榜单会按当时成绩快照显示昵称。

更换邮箱新增 `account_email_codes` 表，包含账号 ID、目标邮箱、验证码摘要、过期时间、尝试次数和认证版本。账号删除时通过外键清除，密码变更时撤销；成功换绑会清理该账号的待验证目标。旧服务忽略此表，不会执行换绑。

会话表新增独立公开 ID、设备概况、创建时间和最近请求时间；旧会话保留，无法还原的创建时间和设备显示为未知。最近请求时间按请求更新，并非精确的用户操作时间；打开设备列表时会在窗口重新获得焦点或约 30 秒后刷新，网络失败时不继续展示旧列表。旧服务不会更新这些新增字段。

更新部署前按 README 的 SQLite 在线备份流程备份数据库，并妥善保管现有 `CODE_SECRET`。回退前先再次备份当前数据库；最稳妥的回退方式是停止服务后恢复经验证的备份。恢复旧备份会丢失备份后发生的变更。保留新增列的数据库可以供旧服务读取，但旧服务不提供新资料功能；恢复前应检查应用和备份版本。

## 尚未完成

账号菜单及账号中心只有在全部相关要求和验收通过后才可标记完成。真实 SMTP 连接、送达与真实操作系统输入法不由内存邮件服务和模拟事件证明。已生成的数据库备份及永久离线设备副本不会被账号注销即时清除，运营方需按其备份保留策略处理。
