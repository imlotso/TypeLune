# 历史记录删除阶段记录

- 历史页提供单条删除及最多 100 条的批量删除，并在确认时说明会撤回关联公开成绩、重新计算统计和个人最佳。游客的纯本机记录可离线删除；有在线成绩的游客记录需要原游客会话和服务端确认。账号记录需要在线操作；连接失败或响应丢失保留重试入口。
- `POST /api/history/delete` 接受 `ids`、可选 `expectedOnlineIds`、旧记录关联与本机冲突标记，以及旧记录的 `expectedRevisions`，按登录账号或游客 Cookie 归属处理。对已提交成绩的撤回、服务端挑战数据删除及账号工作区删除标记，在 SQLite 立即事务中执行；不属于当前用户的成绩不受影响。在线成绩不存在且没有该会话的删除回执，或旧记录的预期修订与服务端不一致时返回冲突。重复请求按回执和删除标记安全重试。撤回成绩保留最小审计事件，并清理该成绩既有审计标签和原因中的个人内容。
- 本机记录、旧版历史及工作区项目按记录标识过滤，收到删除后清除对应旧版副本；导出也排除删除标记。个人最佳、配速参考及统计使用过滤后的记录集合重新计算。对旧响应按项目修订保护，迟到的旧工作区读取不能覆盖已确认的删除。
- 记录删除标记可按现有代次协议整理；`workspace_deleted_records` 保留账号和记录标识来阻止过期写入。`retired_attempts` 保留无正文、无账号归属的随机练习标识，阻止已删成绩或注销账号的练习通过旧恢复凭据重建。`history_deletion_receipts` 保留会话归属和标识用于幂等重试；账号注销时清理该账号回执。上述最小登记在工作区项目配额之外，仍占数据库磁盘空间，并不能即时清理永久离线设备或备份。
- 迁移通过 `CREATE TABLE IF NOT EXISTS` 重入；升级前先用 SQLite 备份 API 或既有容器备份机制备份数据库和持久化卷。旧服务不认识记录删除登记与退役标识：发生删除后不能直接回退旧代码继续写入，否则可能恢复已删除数据；应先停止写入、另存当前数据库，在备份副本上验证安全回退或实现兼容层。实际部署前需结合既有[同步协议说明](2026-11-15-workspace-protocol.md)处理代次和旧设备；本次没有操作生产数据库。
- 已验证超过旧展示上限的历史、详情路由及成绩状态整合。极少数内容摘要标识再次被其他记录占用时仍会阻止删除，避免误删；目前仍按待完善跟踪 D03，见[旧记录说明](2026-11-15-legacy-workspace-records.md)。
