# TypeFlow 排行榜检查与管理

- 对线上仅做匿名汇总和公开接口的只读诊断：已有游客成绩仍存在，分别属于不同的语言、难度和时长；按对应条件查询可以返回，未发现相关管理员下架事件。没有使用生产用户记录进行测试或清理。
- 使用原生产版本的前端和隔离测试服务复现：刷新前查询中文、挑战、2 分钟，刷新后重新进入榜单变成中文、入门、2 分钟。这个筛选变化能解释相应成绩看似消失，但不能证明所有历史现象都由同一原因造成。
- 新版将游客榜／用户榜及语言、难度、时长、模式、严格纠错、文章和时段写入可分享地址。刷新和另一浏览器打开同一地址保留条件；每条成绩显示完成时间。无 `board` 参数的旧接口请求仍可读取混合榜，旧成绩昵称快照不被改写。
- 新提交的游客昵称需以 `visitor` 开头，客户端和服务端都校验。游客默认审核，注册用户普通成绩默认直接发布；后台可独立调整两者的默认审核开关，已有反作弊、暂停及恢复相关复核仍生效。管理员可驳回已经发布的注册用户成绩，也可处理游客成绩。
- 后台可设置公开榜单展示天数，`0` 表示全部；此设置不删除历史。成绩超出展示期限时，个人状态明确显示已发布但当前不展示。后台成绩页支持按本地日历日期和榜单类型筛选；结束日期按本地下一日零点作为不含上界，跨夏令时沿本地日历处理。
- 批量清理要求日期范围、预览数量与摘要、原因及再次确认。服务端在事务中复核匹配集合和管理员权限；筛选结果发生变化时返回冲突，不静默清理新成绩。清理撤下公开成绩并记录审计，保留个人练习历史；单次上限 5,000 条，需要时可缩小日期范围。
- SQLite 与隔离 PostgreSQL 的接口测试覆盖默认策略、旧设置迁移、前缀、分类、已发布成绩驳回、展示期限、日期边界、权限、并发和快照变化；日期转换另覆盖夏令时 23／25 小时及非法日期。两种数据库的 Playwright 流程覆盖游客提交、跨浏览器筛选、管理员通过、用户成绩驳回及日期清理。
