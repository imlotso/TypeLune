# 旧版工作区历史的标识兼容

- 对云工作区值中没有 `recordId` 的旧记录，读取时使用工作区项目 ID，且不把缺失的标识解释为服务端验证成绩。本机无 ID 副本与旧工作区记录只有在内容唯一匹配时才合并；不唯一时保留各条。若生成标识与另一条不同记录冲突，保留两条并阻止误删，提示先导出检查。
- 删除匹配的旧记录时，客户端同时提交工作区 ID 和本机旧标识；两者的删除标记与防复活登记在同一 SQLite 事务内产生，旧设备同步后清理对应本机副本。批量界面仍最多选 100 条；接口允许至多 200 个实际标识以容纳一条记录的两个标识。个人数据导出也按同一规则去重，并不导出内部兼容字段。
- 关联标记可能使满额工作区无法删除旧记录。服务端只对能够从账号自己的无 ID 工作区原值重新计算、且与请求标识完全一致的关联标记进行配额豁免；允许使用受限的旧状态、本机标记及同步代次重建本机标识，每条原记录最多关联一个标识。伪造标识和其他账号的记录无法获得豁免。关联标记仍随工作区返回、可整理，并保留最小删除登记防止旧数据复活。容量页单独显示豁免数量，不把它算作普通项目占用。若旧副本包含无法安全传递或重建的其他元数据，关联标记仍按普通项目计数；工作区已满时可能需要先释放并整理其他项目。
- 新表 `workspace_legacy_record_aliases` 通过 `CREATE TABLE IF NOT EXISTS` 迁移，按账号关联并在注销时级联删除；该最小关联信息在整理后保留以维持配额和防复活语义。部署前用 SQLite 备份 API／既有备份机制备份数据库与持久化卷；旧服务不理解新的关联配额与删除请求，回退前须停止写入、另存当前数据并在备份副本上验证兼容，不能直接用旧服务继续写入。本次未操作生产数据。
