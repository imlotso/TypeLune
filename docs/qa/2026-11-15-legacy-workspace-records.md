# 旧版工作区历史的标识兼容

- 对云工作区值中没有 `recordId` 的旧记录，读取时使用工作区项目 ID，且不把缺失的标识解释为服务端验证成绩。本机无 ID 副本与旧工作区记录只有在内容唯一匹配时才合并；不唯一时保留各条。若旧生成标识与另一条不同记录冲突，本机副本使用包含账号范围的 SHA-256 内容标识单独删除，另一条记录保留；该标识也被占用时，选择确定性的备用标记，并由服务端保存对应关系。摘要使用 [@noble/hashes 1.8.0](https://github.com/paulmillr/noble-hashes/tree/1.8.0) 计算，不把私人正文作为删除标识发送。
- 删除匹配的旧记录时，客户端同时提交工作区 ID 和旧副本对应标记；可核验时使用本机旧标识，否则使用内容摘要标记。两者的删除标记与防复活登记在同一 SQLite 事务内产生，旧设备同步后清理对应本机副本。批量界面仍最多选 100 条；接口允许至多 200 个实际标识以容纳一条记录的两个标识。个人数据导出也按同一规则去重，并不导出内部兼容字段。
- 关联标记可能使满额工作区无法删除旧记录。服务端只对能够从账号自己的无 ID 工作区原值重新计算、且与请求标识完全一致的关联标记进行配额豁免；允许使用受限的旧状态、本机标记及同步代次重建本机标识，每条原记录最多关联一个标识。伪造关联和其他账号的记录无法获得此豁免。仅本机旧副本、冲突副本及唯一匹配但旧状态无法重建的副本另用账号认证和固定格式摘要登记，最多保留 100 个未整理标记；它们不是服务端认证成绩，整理后可继续删除。两类标记仍随工作区返回并保留最小删除登记，容量页单独显示豁免数量。
- 服务端为受认证的本机冲突删除标记返回 `localConflict: true`；备用标记还返回 `localConflictBase`，客户端只根据这些服务端认证字段清理对应无 ID 的本机副本。服务端在同一事务内检查标记和源记录的修订，若删除时出现新的占用则拒绝并保留数据。游客批量删除在本机单个事务内先检查全部标识再写入。账号存在备用标记后，不支持 `local-conflict-v2` 的客户端读取和写入均收到更新提示，以免误解标记；整理后该保护仍有效，本机导出不依赖云端读取。
- 登录账号须完成云工作区及个人历史的读取后才可删除；如果确认弹窗中的旧记录在读取期间发生合并或变更，需重新选择。旧记录删除请求携带所涉及工作区 ID 的预期修订号，服务端在删除事务中核对，避免其他设备在读取后占用同一 ID 时误删；已完成删除的重试仍可幂等处理。旧客户端未携带修订号时不能删除已被占用的旧格式别名。
- `workspace_legacy_record_aliases` 和 `workspace_local_conflict_bases` 按账号关联，在注销时级联删除；该最小关联信息在整理后保留以维持配额和防复活语义。SQLite 通过幂等迁移创建，PostgreSQL 使用显式版本 2 迁移。回退前须停止写入、另存当前数据并在备份副本上验证兼容，不能直接用旧服务继续写入。本次未操作生产用户数据。
- 测试覆盖唯一匹配、歧义、双重占用、满配额下仅本机旧记录的删除、跨账号隔离、重复迁移和注销清理；SQLite 与 PostgreSQL 的多设备浏览器流程均验证删除、整理和过期写入受阻。已查看[容量提示](screenshots/legacy-alias-capacity.png)。用 `809de62` 构建的上一版真实前端连接新测试服务，已验证拒绝旧版同步、[更新提示](screenshots/legacy-client-sync-warning.png)和本机记录保留；这不代表逐一运行过所有历史版本。

## 重现上一版页面检查

在此开发分支使用临时目录构建 `809de62` 的前端，启动当前版本的 `e2e/server.ts` 并让它从该临时目录读取 `dist/client`。测试服务使用独立临时 SQLite 和内存邮箱，不能指向生产：

```sh
project_dir="$PWD"
old_client_dir="$(mktemp -d /tmp/typing-old-client-XXXXXXXX)"
git archive 809de62 | tar -x -C "$old_client_dir"
ln -s "$project_dir/node_modules" "$old_client_dir/node_modules"
(cd "$old_client_dir" && ./node_modules/.bin/vite build)
(cd "$old_client_dir" && E2E_PORT=4210 node --import tsx "$project_dir/e2e/server.ts")
```

在另一个终端执行 `TYPING_LEGACY_TEST_URL=http://127.0.0.1:4210 node scripts/verify-legacy-client.mjs`。完成后停止该测试服务；测试服务自行清理其临时数据库。实际运行的截图另存于上述文件。
